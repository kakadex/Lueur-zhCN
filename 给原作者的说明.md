# Simplified Chinese localization for Lueur — note for the author

**This build:** 1.4.1-zhCN

## What this is

A Simplified Chinese (`zhCN`) localization of Lueur, plus one behavioral finding
about the 15-yard limit that you may want to document upstream.

It is **not** a fork with different features. The addon's logic is untouched:
`Lueur.lua` is byte-for-byte identical to your 1.4.0 (SHA256
`c521178f71d88eabdd13cb85cb61f264b42245f92ff800ace8589384d5edc71d`). Six of your
nine Lua files are unchanged as well.

## What changed

| File | Change |
|---|---|
| `Locales/zhCN.lua` | **New.** 292 strings, one per key in `enUS.lua`. Includes a `L.COMMANDS` table mapping Chinese words to your command names (`/lueur 范围 15` → `/lueur range 15`). |
| `Locales/{deDE,enUS,esES,frFR,ruRU}.lua` | **One line each**: `zh` added to the `language` enum in the help text. Without it, `/lueur language` cannot select Chinese. Everything else is byte-identical. |
| `Lueur.toc` | `## Notes-zhCN` and `## Title-zhCN`, version bumped to 1.4.1, `Locales\zhCN.lua` added to the file list. |
| `Nodes.lua` | **+7 lines**: 13 Simplified Chinese vein names in `VEIN_NAMES.zhCN`. |
| `LICENSE` / `NOTICE.md` | New. Attribution and license statement — see the next section. |

No new CVars, no new saved-variable keys, no API changes. Schema version stays 8.

## The 15-yard limit — measured, not assumed

I tried raising `LIMITS.range` to 40 yards, shipped it, and it did **not** work.
I then wrote a throwaway diagnostic addon and read the values in-game on
`build=16001` (Forever 1.60.1), 2026-11-08 20:52:

| Reading | Value |
|---|---|
| `SoftTargetInteractRange` | **40** — the value really was written |
| `SoftTargetInteract` | 3 |
| `SoftTargetInteractOnlyInRange` | 0 |
| `SoftTargetInteractRangeIsHard` | 0 |
| `nameplateGameObjectMaxDistance` | 60 |
| `ClosestGameObjectPosition(id)` | **nil for all 14 object IDs tested** |

Every CVar was correct, and the client still stopped designating a soft-target
beyond 15 yards, so no nameplate was created and no glow appeared. That matches
the comment you left at `Lueur.lua:76` — I just confirmed it independently and
reverted my change.

This is consistent with the CurseForge description, which already says
"range (5 to 15 yards)". The only thing I would add upstream is a line of user
documentation: *15 yards is a client limit, not a setting.*

## What I could not verify

I have no Lua interpreter on this machine, so the checks are static only:

- key parity with `enUS.lua` (292 keys, no duplicates, no missing)
- format-placeholder parity (290 single-line strings, `%s`/`%d`/`%%` counts match)
- help list length (30 lines on both sides)
- block balance (`function`/`if`/`for`/`end`) on 9 files
- top-level local count: **198 of the 200 allowed** by Lua 5.1 — the same as your
  1.4.0, so no headroom was consumed

**Not verified:** that the addon loads in-game, that the Chinese glyphs render,
that `/lueur help` wraps correctly in the chat frame, and that
`/lueur 范围 15` dispatches as expected. Those need a real client.

## A caveat on the Chinese vein names

The 13 names in `Nodes.lua` were written from Classic-era Simplified Chinese
terminology, without checking each one against a live `zhCN` client. Comparing
against GatherMate2's `zhCN` tables afterwards showed several differences — for
example GatherMate2 has `铜矿` where I wrote `铜矿脉`, and `精铁矿脉` where I wrote
`因迪里姆矿脉` for the Indurium vein. If a Chinese client names a vein differently
from my table, the minimap icon falls back to the generic profession icon, so the
failure is cosmetic — but the table probably needs a native speaker's pass.
